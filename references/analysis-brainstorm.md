# 分析头脑风暴模式（可选 · 默认关）

这是一条**可选**的出口，只在逆向分析卡在"不知道怎么切入"时才开。它不是必经步骤，默认关闭；
不开它，整套流程一个字节都不变。它要解决的是**分析瘫痪**：六类逆向手段迟迟给不出决定、找不到
授权面、不确定走哪条复刻路线时，一个人对着二进制干瞪眼。

它的价值是把"多角色对辩"变成结构化产出，而**不是**又开一场没有结论的会。所以它有一条硬规矩：

> **讨论结束 ≠ 完成。收尾必须在 `analysis/ROUTE-DECISION.yaml` 里落定一条真实路线，否则校验器会红。**

这正是本项目最贵的教训——"三小时只出文档"——的反面。头脑风暴如果不落到一个决定，它就是纯消耗，
按缺陷对待，不是产出。

## 什么时候开

同时满足才值得开（否则别开，空转比不开更贵）：

- 你正处在 EXE 分析阶段（`start-here.ps1` 会在"六类未逐类决定"这个压力点旁打印开启提示）；
- 你**确实卡住了**：不确定先静态还是先动态、找不到授权校验入口、几条复刻路线拿不定主意；
- 一个人往下推只会凭印象猜，而不是有证据地走。

只是"想更全面一点"不构成开的理由。卡住才开。

## 怎么跑（主对话当桥，宿主 agent 用自己的子代理能力）

这个 skill 是方法论，它自己不 spawn 代理。**由宿主 agent（Claude / Codex / Cursor 等）用自己的
Task / 子代理能力**按下面的协议跑：

1. **主对话当桥**：主对话是唯一连接各角色的枢纽，负责派活、收集立场、综合收敛、最后落笔。角色之间
   不直接长篇互聊，都回到主对话汇总——避免 N² 噪声。
2. **派 2–4 个对立角色**（见下），每个角色只做一件事：给出一个**切入方案** + 对别人方案**挑漏洞**。
   对辩的价值在"互相找漏洞"，不是各说各话。
3. **1–2 轮，要快**：第一轮各出方案 + 互相指问题；（可选）第二轮针对最大分歧再交锋一次。就收。
4. **主对话收敛并落笔**：把结论写进 `analysis/ROUTE-DECISION.yaml`（选定 `chosen_route` + 写清
   `route_rationale`），把过程记进 `analysis/BRAINSTORM-LOG.yaml`，并把它的 `status` 改成 `resolved`。

## 四个默认对立角色

可增删，但保持"彼此对立、能互相证伪"这个性质——四个都同意的会议不产生信息。

| 角色 | 主张怎么切入 | 它专门盯谁的漏洞 |
|---|---|---|
| `static_structure` 静态结构派 | 先 `dumpbin` / DIE / 字符串 / 资源摸清 PE 结构与是否加壳，再谈别的 | 反对没摸清结构就上动态（盲调） |
| `dynamic_debug` 动态调试派 | 直接受控运行 + `x64dbg` / Procmon 跟授权分支，最快定位校验点 | 盯"纯静态推断"离真实行为太远 |
| `known_tool_reuse` 已知工具复用派 | 先 `discover-tools` + 查 `knowledge/verified/`，别为这个目标重复造轮子 | 盯"又要新装一堆工具"的浪费 |
| `skeptic` 怀疑者 | 任何 payload 层结论先过 `PROTECTION-PROFILE`，警惕容器/壳层假发现 | 盯前三方都没先确认"看到的是不是本体" |

怀疑者这一角色是硬要求：它对应 `validate-product-state.ps1` 里的 layer 门——在容器/壳上做的四类
发现都能产出真实哈希、都能过前面的门，但描述的全是外层。有个角色专门盯这件事，能在写进档案前就拦住。

## 收尾：必须落到一个决定

`analysis/BRAINSTORM-LOG.yaml` 的 `status` 一旦改成 `resolved`，`validate-product-state.ps1`
就会检查：

- `analysis/ROUTE-DECISION.yaml` 必须存在；
- `chosen_route` 不能还是 `UNKNOWN`，且必须是 `allowed_routes` 里的合法值；
- `route_rationale` 不能还是 `UNVERIFIED`/空——要写清为什么选这条、否掉别条的理由。

任何一条不满足，`status: resolved` 就判红。想删掉 `BRAINSTORM-LOG.yaml` 让门失效当然可以——但那
等于"我没开过这场头脑风暴"，也就没有任何东西要落地了。门只惩罚一种情况：**开了会、宣称收敛了、却
没落下决定。**

选路线不是"首测最快"就行：`ROUTE-DECISION.yaml` 顶部写了要先过 交付类型/覆盖率/真实副作用/可回滚/
可重放 五关，再在合格里取最快。头脑风暴的产出要经得起这五关，而不是把最省事的那条写上去。

## 它不做什么

- 不替代 `gap-classify.ps1`：头脑风暴是"不知道怎么开始"，`gap-classify` 是"某一类真跑了却失败"。
  先用它想清楚切入，真动手后某类卡死再用 `gap-classify` 如实记 blocked。
- 不改变任何证据门：路线选完，后面的绑定证据、真跑证据、回滚证据一条都不少。
- 不是源码复用轨道（`track: source`）的默认步骤：源轨道有自己的源码、不做六类逆向；这套主要服务
  黑盒 EXE 分析。源轨道若要借用，同样以"必须落到一个已决路线"为收尾。
